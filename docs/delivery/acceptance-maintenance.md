### 群管理与共用 NapCat

- [ ] 空环境依赖安装、建库、前台启动、管理员登录与健康检查成功。
- [ ] NapCat 反向 WebSocket 身份正确，测试消息形成影子记录，真实动作仍关闭。
- [ ] 巡检 HTTP 连接与主服务 WS 并存；启动、暂停、退出巡检不会改变主服务群开关或中断主服务。
- [ ] 准备服务化、睡眠/重启与故障恢复时有明确责任人和维护流程，不把一次启动当作无人值守验收。
- [ ] 如需启用真实动作，按公司批准范围单独验证保护角色、白名单、去重、审批和未知结果；不借巡检安装自动开启。

### 空间巡检

- [ ] 接收方自己登录空间，来源账号和访问账号显示准确。
- [ ] 单群、多群有重复成员的任务，去重数与逐群导出关联一致。
- [ ] 明确限制页与权限/未开通/维护页区分正确，未命中仍待确认。
- [ ] 暂停、正常退出、重开、载入、继续后已完成结果和历史观察不丢失。
- [ ] 登录过期、断网、未知页面、平台拦截均保存进度并正确暂停；不自动绕过拦截。
- [ ] 自选导出目录重开后保留；失联磁盘明确报错，旧结果仍在原位置。
- [ ] 导出群名、群号、QQ、状态、观察时间与保存记录对应；未完成成员不被当作正常。
- [ ] 记录实际访问数、复用数、耗时、失败/暂停原因及人工介入，不用累计完成数推算腾讯固定阈值。

真实检查需使用公司授权范围，不为测试刻意持续触发风控。已完成部分可导出；遇平台拦截不能把“本地还剩多少名额”当作继续请求依据。

## 数据、备份与恢复

| 数据 | 默认位置/用途 | 备份注意 |
| --- | --- | --- |
| 主数据库与媒体 | 项目配置所指数据库及 `data/` 资源 | 使用现有一致快照机制；不在运行中裸复制主 DB 文件冒充备份 |
| 主项目私有配置 | 接收方本机 `.env` 与 NapCat 配置 | 分别保管，不随源码包和普通诊断流转；现有公开恢复模板不包含密钥 |
| 巡检任务 | `%LOCALAPPDATA%\QQSpaceInspector\tasks` | 群快照、观察、续扫依据；CSV 不能替代 |
| 巡检历史缓存与设置 | 同目录 `observations.sqlite3`、`export-settings.json` | 当前未被主项目每日备份覆盖 |
| 巡检导出 | 窗口显示的自定义总目录，默认桌面 | 与任务记录分别保留；更改位置不会搬移旧结果 |
| 巡检浏览器 | 同目录 `browser/` | 含登录会话，不放进通用备份交付包或发给别人；换机正常重新登录 |
| 巡检运行环境 | 同目录 `runtime/` | 可重新安装，不作为任务备份替代品 |

现有 `app.reports.scheduled_backup` 初始化及运行检查要求真实 Git 仓库、干净工作区和可追溯提交。因此候选 ZIP 不能直接套用附带的每日备份注册脚本。维护人员须先适配可验证发行包或采用获批 Git 部署，再核验调度、首次执行与隔离恢复；不伪造仓库或跳过锁、完整性检查。

在自动配套备份完成前，巡检可由维护人员在**正常关闭巡检后**复制获批的任务目录、历史缓存及其 SQLite 辅助文件、导出设置和各导出目录到私有备份位置；不只复制仍在运行的数据库主文件。不要夹带 `browser/` 或整个运行环境。备份和恢复清单均须核对来源、目标、可恢复性，删除原任务须另有明确授权。

异机恢复先在隔离位置验证；重新配置同一来源账号、使用原空间观察账号正常登录，再核对任务是否能载入与继续。不能承诺当前工具脱离项目/NapCat 配置仍可离线使用；导出虽不访问 QQ，启动服务对象仍需这些本机配置存在且可解析。

## 版本与升级

同一交付包的主服务、巡检和手册由相同来源提交生成，不把不同版本的 `app/`、迁移文件或规则拼在一起。升级前记录旧提交、备份和数据兼容性，确认主服务维护窗口；数据库回滚与覆盖恢复须另行评估和批准。

巡检应先暂停并正常退出，再更新源码和按锁定依赖重新安装。重开后检查原任务列表、导出位置与账号关系；不能删除 AppData 来代替升级。只更新巡检入口不自动批准主服务重启或数据迁移。

## 故障交接

公司维护人员收集：包版本/提交、操作步骤、界面提示、任务时间、未完成数量、脱敏截图及是否可复现。只提供问题所需最少信息；不提供完整浏览器目录、密码、Cookie、Token 或整库成员数据。

普通操作人员先保存/导出当前结果，再按提示联系维护人员。维护人员区分群目录连接、空间登录/页面、任务数据和主服务问题，不因巡检暂停就改群权限、重启生产或放松异常判断。
