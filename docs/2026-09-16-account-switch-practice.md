## 三、遇到的问题与解决方法（★核心）

### 问题① 换号后系统显示未连接（connected=False）

- **现象**：NapCat 已登录新号，但系统 healthz 仍为 `degraded / connected=False`。
- **原因**：新登录的 NapCat 实例的**反向 WS 配置缺失或未启用**（NapCat 不会自动知道要连本系统）。
- **解决**：按第二节第 3 步添加「WebSocket 客户端」并保存；保存后 `connect_count=1`。
- **排错**：若保存后仍连不上——把「**SSL证书验证**」开关**关掉**再保存（`ws://` 明文本机回环无需证书，个别版本开着会拦截）。

### 问题② 验证连接的正确方式

```
# 1) 健康检查（无需 Token）
GET http://127.0.0.1:8001/healthz
# 关注：onebot.state=ready、connected=true、login_state=online、connect_count≥1

# 2) OneBot 状态（需 Bearer Token，值见 .env ONEBOT_ACCESS_TOKEN）
GET http://127.0.0.1:8001/onebot/status
# 关注：self_id=530297362（新号）；group_last_event 显示各群最后消息时间
```

- **注意**：`healthz` 里的 `self_id` 字段可能为空，**以 `/onebot/status` 的 `self_id` 为准**。

### 问题③ "后台群列表没变"是正常现象（本次确认）

- **现象**：换号后管理后台的群管理列表仍是原来的群。
- **解释**：群管理列表 = **授权配置**（按 QQ 群号存储），**与登录哪个账号无关**——这是设计：换号不改变管理范围、记录、规则。需要的是"补授权新号独有的群"，而不是"换一套后台"。

### 问题④ 如何查看新号所在的群（NapCat 入口纠错）

- **纠错**：NapCat WebUI **没有**独立的"群聊天/群组管理"列表页。
- **正确入口**：左侧「**接口调试**」→ 选择 `get_group_list` → 执行，返回 JSON 群列表（含群号、群名、人数）。
- **备选**：登录该号的手机 QQ 直接查看群列表。

### 问题⑤ 新号的群很多（140+），哪些该纳入管理

- **原则**：**不自动全接管**——管理范围必须明确（动作有真实影响）。
- **本次口径（负责人指令）**：所有 **member_count > 500** 的群全部纳入 → 13 个（11 个既有 + 2 个新增）。
- **后续其他群**：按需单独授权；"自动发现 + 人工确认"的同步功能为候选（未实施）。

### 问题⑥ 换号后动作权限（撤回需要新号是群管理员）

- **要点**：QQ 权限模型——只有**群主/管理员**能撤回他人消息。新号需在每个授权群具备管理身份。
- **风险控制**：换号首日拉急停观察；即使误触发，动作失败也会留 `FAILED` 记录（**不静默**），不会假装成功。
- **建议**：换号后逐个群确认新号身份（群主 ≥ 管理员）。

## 七、常见疑问：不同账号的群集合不一样怎么办？

**背景**：新号所在的群与旧号可能不同（有的群没了、有的群多了）。

- **原来管、新号不在的群**：授权配置**保留**，但系统收不到该群消息（NapCat 不在群里），实际停止工作；记录不丢。处理：把新号拉进群（配置自动恢复生效）或手动关闭该群配置。
- **新号独有的群（未授权）**：**不会自动接管**（设计上管理范围=明确授权），按口径人工授权（本次">500 人"批量口径）。
- **规则是否需要重配**：**不需要**——黑/白名单、豁免、动态规则均为**全局一份**，换号自动沿用。
- **为什么不是"新账号 = 新后台、规则再同步一份"**：一个后台（一套数据）多通道（可换账号）能保证——
  ① 规则单一事实源（不存在两套后台规则漂移）；② 历史与违规累计跨号连续（同一批群/用户不清零）；
  ③ 审计连续（谁在何时做了什么不断链）；④ 换号只是更换"眼睛和手"（收/发通道），不是重建系统。
