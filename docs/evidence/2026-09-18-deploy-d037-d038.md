## 5.2 部署后核查发现并修复的缺陷：结构性规则编号冲突（14:56 修复并重启）

**缺陷**：结构性规则最初误用内置规则的 `R0xx` 编号段——`R007` 与内置
`contextual_ad_terms` **撞号**，并被一并加入 `review_gate._HARD_EVIDENCE_RULES`，
后果是**内置规则**被复核门当成独立硬证据，其原本的自动处罚门槛被放宽。

**实测影响**：部署（06:36）后共 **3 条**判定被放宽（均满足"仅 R007、无其它硬证据"且判为
`violation_high`：判定 #14383 / #14415 / #14447）。这 3 条**全部落在急停窗口内**
（06:38–06:46），其动作意图均为 `SKIPPED` → **真实撤回 0 次**。

**修复**：
- 编号改为语义前缀：`R_FORWARD_RECORD` / `R_GROUP_CARD`（彻底脱离 `R0xx` 段）
- 复核门集合改为"内置三项 `{R001,R003,R006}` + `decision.py` 导出的结构性常量"
- 新增 2 条回归：结构性规则编号不得匹配 `R0\d\d`；硬证据集合不得包含 `R002/R004/R005/R007`
