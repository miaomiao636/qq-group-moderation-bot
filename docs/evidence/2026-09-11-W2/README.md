## 三个关键发现

### 1. 限流器会静默降级审核（已修复，真实运维风险）

`.env` 原 `AI_PER_MINUTE_LIMIT=30` / 默认日上限 1000。批量回放实测 **64 次调用被
`ai_rate_or_budget_limited` 拦截**，直接造成召回从 83% 暴跌到 59% 的假象。

- **生产风险**：群内突发刷屏/攻击时，同样会静默降级，运营方却以为审核在工作。
- 已修复：日志告警（`app/moderation/ai.py`）+ 参数上调 `AI_PER_MINUTE_LIMIT=90`、
  `AI_DAILY_CALL_LIMIT=3000`。
- **遗留**：告警只是留痕，**仍需接入人工通知**（见 W3/通知渠道缺口）。

### 2. 延迟由供应商波动主导

同一模型同一批图，多次测量 p95 在 **12.9s ↔ 17.9s** 间摆动（图片门槛 15s）。
这属于服务端负载波动，**不是配置可稳定控制的**。

已尝试并放弃的捷径：提高灰区下界 0.60→0.70 虽然让图片 p95 达标（14.0s），
但召回跌到 76.3%——该参数同时控制"是否复核"与"是否转人工"，无法独立调节。

### 3. 精确率的 2 个假阳性是跨轮次翻转

同一批图片的假阳性在第 6/7 轮之间为 1↔2 张，是**模型自身输出不稳定**，非规则错误。
且 101 条负例只允许 0 误报，**样本量不足以严格证明 99% 精确率**（需数百条负例）。
