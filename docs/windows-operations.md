# Windows 24×7运行与恢复要求

## 目的和适用范围

本文定义项目在单台Windows 11专用机上长期运行时必须满足的电源、启动、重启、更新、状态恢复、监控和人工接管要求。

本文是实施约束，不代表相关自动化已经完成。实际服务安装、启动和恢复命令由 `NEXT_TASKS.md` 中的 `T-404` 实现并在本文件补充验证结果。

## 正式测试环境决策

- 项目负责人已选择一台空白Windows电脑作为正式整机测试环境。
- 优先使用Windows 11 x64；首次测试时必须记录Windows版本、版本号、CPU架构、补丁日期、内存、磁盘和网络方式，不能仅写“Windows电脑”。
- 代码通过Git同步，Windows端重新创建 `.venv`，不得从Mac复制虚拟环境、缓存或含密钥的 `.env`。
- 测试凭据只保存在Windows本机环境变量或系统凭据存储；W1至W4使用隔离QQ账号和隔离测试群。
- GitHub Actions Windows Runner只负责代码兼容性，不能替代本机QQ、NapCat、Windows Service和24×7恢复测试。

## 分阶段测试计划

### W0 基础兼容性基线

进入条件：R-101所有整改项通过主审，远程Ubuntu、Windows和运行时依赖CI均有真实成功记录。

在空白Windows电脑验证：

- 从Git仓库干净获取指定提交，不复制Mac的 `.venv`。
- 安装Python 3.12与uv，执行锁定依赖安装。
- 验证Alembic全新升级、降级、重新升级和head版本拒绝。
- 验证非法配置拒绝、生产空白密码拒绝和 `WEB_PORT` 实际监听。
- 执行pytest、mypy、ruff检查与格式检查。
- 从项目目录之外启动，确认配置、迁移脚本和SQLite数据库仍指向预期位置。
- 本阶段不配置真实QQ、NapCat或模型密钥。

退出标准：所有命令通过，记录提交号、Windows版本、命令、时间和脱敏日志；无项目目录外数据库漂移或测试目录清理失败。

### W1 QQ官方链路

进入条件：W0、T-001和T-102通过。

在隔离测试群验证文字及各类媒体事件、事件验签、去重、媒体元数据、官方撤回、禁言3,600秒和86,400秒、首次警告、权限不足、限流和失败审计。此阶段审核判断可以使用固定测试结果，不要求完整模型。

退出标准：T-001样本全部能稳定转换；重复事件不重复执行动作；官方能力限制及降级方案有真实记录。

### W2 核心安全模式端到端

进入条件：W1以及T-002、T-103、T-104、T-201至T-203、T-301、T-302、T-401和T-402通过。

NapCat保持关闭，验证文字与多模态识别、第一次和第二次处罚、案件证据、编号审批、日报周报、误判恢复、白名单和人工QQ客户端踢人闭环。

退出标准：安全模式在NapCat完全不可用时仍可完成识别、处罚、案件、报告和人工结案；自动处罚达到项目精确率与召回率门槛。

### W3 无人值守与灾难恢复

进入条件：W2及T-404实现完成。

验证Windows Service、屏幕关闭与锁屏、进程崩溃、系统重启、断网、模拟断电、Windows更新、磁盘不足、数据库占用、备份恢复、外部心跳和 `UNKNOWN` 动作人工复核。

退出标准：无需人工打开终端即可恢复官方审核；结果未知的处罚不会重复；所有演练有时间、结果和日志证据。

### W4 可选NapCat

进入条件：W3、T-303和T-304通过，并且项目负责人再次明确批准。

使用没有重要资产的专用测试QQ，验证数字身份镜像、映射冲突、一次性审批令牌、批量编号、幂等、QQ验证失败和自动回退人工。不得尝试绕过QQ验证或风控。

退出标准：无审批、映射非 `VERIFIED`、白名单或令牌异常时踢人调用为0；测试期间误踢为0；NapCat失败不影响官方审核。

### W5 最终分阶段验收

进入条件：W2与W3通过；如项目负责人决定启用NapCat，还需要W4通过。

按T-403执行影子审核、官方自动撤回与禁言、人工踢人和连续稳定性观察。NapCat是可选增强，不是核心安全模式最终验收的前置条件。

退出标准：满足T-403及 `PROJECT_CONTEXT.md` 的验收指标，连续运行期间没有不可解释的重复事件、权限越界、状态错乱或误踢。

## 核心原则

- 屏幕可以自动关闭，Windows可以锁屏，但主机不能进入睡眠或休眠。
- 睡眠期间CPU和网络任务会暂停，不能作为24×7实时审核方案。
- 审核服务必须在没有打开终端窗口的情况下运行，并在Windows启动后自动恢复。
- 高影响动作的结果如果不确定，重启后不得自动重复执行。
- NapCat恢复失败不能阻断官方审核；系统必须切换为人工QQ客户端踢人。
- 不以自动登录、绕过QQ验证或频繁重登作为恢复方案。

## Windows和硬件要求

### 电源设置

- 接通电源时，允许屏幕在5～10分钟后关闭。
- 接通电源时，将“使设备进入睡眠状态”设置为“从不”。
- 禁止自动休眠；笔记本合盖时如需继续运行，应设置为“不采取任何操作”并保证散热。
- 禁止网卡因节能被系统关闭。
- 专用机不得依赖电池长期运行；条件允许时配置UPS。

### 断电恢复

- BIOS/UEFI启用“交流电恢复后自动开机”或同等设置。
- 短时断电由UPS维持运行；UPS电量不足时应执行受控停机，避免SQLite和媒体文件损坏。
- 重新来电后，Windows、审核服务和健康监控应自动启动。

## 组件启动与恢复模型

### 启动顺序

1. 本地磁盘、数据目录和系统凭据可用。
2. 数据库迁移和数据库健康检查通过。
3. 审核服务启动。
4. 媒体任务执行器和报告调度器启动。
5. QQ官方机器人连接并完成就绪检查。
6. 便捷模式下才启动NapCat连接和身份映射检查。
7. 健康监控确认所有必需组件状态并发送恢复报告。

前置组件未就绪时，后续组件必须等待或降级，不能循环高速重启。

### Windows服务

- 审核服务、媒体任务执行器、报告调度器和健康监控应安装为Windows Service或具备等效可靠性的受监督进程。
- 服务启动类型使用“自动（延迟启动）”。
- 第一次和第二次崩溃可以自动重启，连续失败后使用指数退避并告警。
- 开发用的 `uvicorn --reload` 不得用于生产运行。
- 服务必须使用专用低权限Windows账号，只授予数据目录、日志目录和系统凭据的必要权限。

### NapCat特殊限制

- NapCat具体启动方式、是否依赖交互式用户会话，必须在隔离测试机验证后记录。
- 如果QQ要求扫码、设备确认或安全验证，系统只能告警并等待人工处理，不得反复自动登录。
- NapCat未就绪时隐藏NapCat踢人入口，所有待踢案件转为人工处理。
- 不为了无人值守而降低Windows登录安全或保存明文QQ凭据。

## 应用状态恢复

### 可安全重试

- 尚未开始的媒体分析任务。
- 具备内容哈希和幂等键的模型调用。
- 尚未生成成功记录的日报和周报任务。
- 只读同步和健康检查。

### 不得盲目重试

- 撤回、禁言、警告和踢人等外部动作。
- 已发送但未取得明确响应的通知。
- 审批令牌已消费但结果未知的NapCat任务。

重启时，执行中的外部动作应转为 `UNKNOWN` 或等效的“结果待确认”状态。系统先查询平台状态；无法查询时进入人工复核，不能直接重放。

### 幂等要求

- 事件去重键至少包含来源和来源消息ID。
- 自动处罚键至少包含案件、动作类型和目标。
- NapCat踢人键至少包含案件ID、数字群号和数字QQ号。
- 报告任务键至少包含报告类型和统计时间窗口。
- 幂等记录必须落库，不能只保存在进程内存。

## Windows更新维护流程

不永久关闭Windows安全更新。通过维护窗口控制更新和重启：

1. 将Windows活动时间覆盖正常群聊高峰，维护窗口安排在低峰期。
2. 通知管理员即将维护，并暂停新的自动处罚。
3. 停止接收新的异步任务，等待可安全完成的任务排空。
4. 对SQLite数据库执行一致性检查并生成可恢复备份。
5. 记录未完成案件、队列位置和外部动作状态。
6. 安装更新并重启。
7. 按启动顺序自动拉起组件。
8. 验证数据库、官方机器人、队列、磁盘、模型和报告调度状态。
9. NapCat需要验证时保持人工模式，不阻塞官方审核。
10. 健康检查通过后恢复自动撤回和禁言，并向管理员发送维护结果。

维护失败时保持“只记录和告警”或人工模式，不能在部分组件异常时自动恢复高影响动作。

## 健康监控与告警

至少监控：

- 进程和Windows Service状态。
- QQ官方机器人连接状态及最后事件时间。
- NapCat连接和QQ验证状态。
- 数据库可写性、WAL增长和最近备份时间。
- 媒体队列长度、最老任务等待时间和失败率。
- 模型超时、限流、熔断和费用预算。
- 动作失败率、未知结果动作和待人工案件数。
- 磁盘剩余空间、系统时间和报告调度状态。

健康检查需要区分：

- `live`：进程仍在运行。
- `ready`：数据库和必需依赖可用，可以接收新任务。
- `degraded`：官方审核仍可运行，但NapCat或部分模型不可用。

主进程不能只依靠自身发送故障告警。T-404需要提供独立的本机监控；正式运行时建议增加外部心跳监测，以发现整机断电或断网。

## 备份和恢复演练

- 每日备份数据库，备份文件不得与唯一数据库位于同一物理磁盘。
- 备份必须加密并执行保留期清理。
- 每月至少执行一次恢复演练，验证迁移版本、案件、审批、幂等记录和报告数据可读取。
- 数据库恢复后，所有结果不确定的外部动作进入人工复核。

## T-404验收要求

- 屏幕关闭并锁屏2小时后，消息接收和健康检查持续正常。
- Windows重启后，无人工打开终端，必需服务在规定时间内自动恢复。
- 服务进程被强制终止后可以按退避策略恢复，并留下告警和审计记录。
- 更新维护演练可以暂停、备份、重启、健康检查和恢复。
- 模拟断网、断电重启、数据库占用、磁盘不足和NapCat验证失败时，系统进入正确降级状态。
- 重启前结果未知的处罚不会自动重复执行。
- NapCat无法恢复时，官方审核继续运行，踢人案件自动转人工处理。
